---
title: "Webhooks"
description: "Every webhook event type HIFI supports, grouped by resource."
---

Event types follow one of two shapes: `RESOURCE.EVENT` for one-time events like creation or deletion, or `RESOURCE.EVENT.VALUE` for events tied to an enum - most commonly `RESOURCE.STATUS.<STATUS>`, one per value the resource's `status` field can take. Use the exact strings below in `subscriptions` when [registering an endpoint](/v3/core/webhooks/overview#register-an-endpoint), or call [`GET /webhook-endpoints/event-types`](/v3/core/webhooks/overview#list-supported-event-types) for the same list at any time.

<Info>
  A resource with both a `CREATED` event and a `STATUS` enum that includes a `CREATED` value fires both `RESOURCE.CREATED` and `RESOURCE.STATUS.CREATED` when it's first created - they're two distinct events, not duplicates of each other.
</Info>

## User

| Event Type | Description |
| --- | --- |
| `USER.CREATED` | A user was created. |
| `USER.STATUS.ACTIVE` | The user is active. |
| `USER.STATUS.INACTIVE` | The user is inactive. |
