---
title: "KYC Events"
description: "You can expect to receive KYC webhook events whenever you update a user's KYC data, submit KYC to unlock a rail, or receive KYC status updates for any rail you've submitted."
---


## Types

- **KYC.DATA.UPDATE**: Updates to the user's KYC data.
- **KYC.STATUS.CREATE**: Submission of the user's KYC status for any rail.
- **KYC.STATUS.UPDATE**: Update of the user's KYC status for any rail.
- **KYC_LINK.CREATE**: Creation of a KYC Link.
- **KYC_LINK.UPDATE**: Submission of a KYC Link.
- **KYC.RFI.OPEN**: An onboarding request for information (RFI) was issued.
- **KYC.RFI.CLOSED**: The user's onboarding RFI was resolved or expired.

## KYC.RFI

Sent when an onboarding [request for information](/features/rfi) opens or closes. The data object has the same structure as [KYC.STATUS](#kyc-status) for the `USD` rail, including its `rfi` object. On `KYC.RFI.OPEN`, `rfi` describes the open request. On `KYC.RFI.CLOSED`, it is `null`.

Transaction RFIs are sent as `ONRAMP.RFI.*` and `OFFRAMP.RFI.*` instead. See [Onramp Events](/webhooks/onramp-events#rfi-events) and [Offramp Events](/webhooks/offramp-events#rfi-events).
